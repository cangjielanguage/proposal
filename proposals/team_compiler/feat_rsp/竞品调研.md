# 业内 rsp 解析规则调研

> **结论先行**:不存在单一"GNU 风格"。解析器按"版本 × 宿主"分四类行为,但存在一个所有解析器共同遵守的**安全公共子集**(§3)——项目读写 rsp 按它来即可。
> **判定原则**:不看 `-v`/`-###`(对特殊字符二次转义展示),以解析后的真实 argv 为准(strace 抓 cc1 / driver 报错点名)。证据:`/tmp/opencode/rsp_demo/verify/`(clang 42+5 用例、gcc/ld 38 用例、Windows llvm-mingw 15 一批)。

## 1. 各解析器规则总表

| 规则 | GCC 11.4¹ | clang 14(全平台) | GNU ld 2.38 | ld.lld/ld64.lld(Linux/macOS 宿主) | ld.lld(MinGW 驱动 × Windows 宿主)² | bash(仅参照) |
| --- | --- | --- | --- | --- | --- | --- |
| 空白切 token | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `"` 包空格、可跨行 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `'` 引号 | ✓(内 `\` 仍转义) | 同左 | 同左 | 同左 | ✗(`'` 是普通字符) | ✓(内全字面) |
| `\X` → 字面 `X` | 引号内外都转 | 引号内外都转 | 引号内外都转 | 引号内外都转 | ✗(`\` 字面,仅紧邻 `"` 时特殊) | 双引号内仅 `` $ ` " \ `` 5 种 |
| `\<newline>` | 换行进 token | 换行进 token | 换行进 token | 换行进 token | 字面 | 续行拼接 |
| `#` 注释 | ✗ | ✗ | ✗ | ✗ | ✗ | ✓ |
| `$` / `~` / glob 展开 | ✗ | ✗ | ✗ | ✗ | ✗ | ✓ |
| 空串 `""` | 保留 | **丢弃** | 保留 | 保留 | 未测 | 保留 |
| 未闭合 `"` | 吞到 EOF | 吞到 EOF | 吞到 EOF | 吞到 EOF | 吞到 EOF | 语法错误 |

¹ GCC 在向 bash 演进:WinLibs GCC 16.1.0 初测已部分吻合新 libiberty(双引号内仅 5 种转义、单引号字面化),与 GCC 11 已分叉。
² lld 的 tokenizer **跟着驱动走**:MachO 驱动(ld64.lld)无条件 GNU 规则(`lld/MachO/DriverUtils.cpp:86`),故 macOS 上与 clang 同款;GNU/ELF 驱动与 MinGW 驱动按宿主 OS 分支(Windows→CRT,其他→GNU),ELF 驱动另可用 `--rsp-quoting=posix|windows` 显式指定(`lld/ELF/DriverUtils.cpp:77-89`)。**Windows 宿主上的 ld.lld(MinGW)是全家唯一 CRT 规则者**。GNU ld 与 gcc 同源 libiberty(`expandargv`/`buildargv`)。

**常见误区**:clang 的单引号**不是** bash 单引号——引号内外 `\` 一律转义(`'c:\users'` → `c:users`),引号只负责包空格与闭合。

## 3. 汇总规则(所有解析器的公共安全子集)

**手写 rsp(读侧):**
1. 参数用空格分隔;含空格用 `"..."` 包裹(允许跨行)
2. 路径一律用正斜杠 `c:/x/y`——**不要裸写反斜杠**(`\t` 等会被当转义吃掉)
3. 不要用 `#` 注释、不要用 `\` 续行、不要用单引号(各家语义不一致)
4. 不要用 `""` 表达空参数(clang 会丢弃)
5. 不要指望 `$`/`~`/glob 展开

**工具生成 rsp(写侧,cjc 场景):**
1. 每参数一行;程序名 argv[0] 不写入
2. 含 空白/`"`/`'`/`\`/`#` 的参数 → 包 `"..."`,内部 `"` → `\"`
3. `\` 的转义按**宿主 OS 分支**:GNU 宿主 `\` → `\\`;Windows 宿主 ld.lld 是 CRT 规则(`\` 不转义,仅处理与 `"` 相邻的情形)——与 lld 自身 `getQuotingStyle()` 同构
4. 空参数不得输出 `""`,在参数层规避(如 `-Dfoo=` 形式承载空值)
5. 行尾统一 `\n`(不要 CRLF);`@` 展开不看内容,生成方保证 rsp 是文本

生态先例:GCC 链接参数长时 collect2 自动生成临时 rsp 传给 ld(`gcc -v` 可见 `@/tmp/xxx.rsp`),即"工具侧自动 rsp"的现成先例;clang 14 无此机制。

## 4. 遗留分歧点

- **GCC 版本漂移**:GCC 16(新 libiberty)向 bash 演进(单引号字面化、5 种转义、`\`+换行变续行),与 GCC 11 行为已分叉,长期需盯版本;
- **Windows 宿主 ld.lld(MinGW 驱动)走 CRT 规则**:GNU 风格序列化器的 `\\` 读回为字面双反斜杠——Win32 容忍、可正常链接,但**非精确往返**(`\\?\` 长路径、UNC 有风险)→ 按宿主分支序列化器(§3.3);好消息:macOS 的 ld64.lld(MachO 驱动)无条件 GNU 规则,序列化器在 mac 上是**精确往返**;
- Windows gcc 16.1.0 实验数据内部矛盾、Windows ld.lld 空串行为未测,均待 argv 级复测。
